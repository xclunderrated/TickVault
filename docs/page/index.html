TICKVAULT · PYTHON 3.11+

Getting started

Download and validate hourly tick archives, then read exact UTC windows from your local copy.

i

01 · INSTALLATION

Install the library

TickVault 0.3.0 is available from the repository branch and has not been published to PyPI. Install Python 3.11 or newer. HDF5 support is optional.

POWERSHELL · WINDOWS
py -3.13 -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev,hdf5]"
.\.venv\Scripts\tick-vault --help
LINUX / MACOS
python -m pip install -e ".[dev,hdf5]"
python -m tick_vault --help

For runtime only, install with python -m pip install -e .. Add [hdf5] only when you need HDF5 exports.

02 · DOWNLOAD

Fetch an hourly archive

Download calls are asynchronous. Naive datetimes mean UTC; timezone-aware values are converted to UTC. The downloader obtains complete historical hours overlapping the interval.

BOUNDED PYTHON EXAMPLE
import asyncio
from datetime import UTC, datetime
from tick_vault import download_range

async def main():
    report = await download_range(
        "EURUSD",
        datetime(2024, 1, 15, 12, 30, tzinfo=UTC),
        datetime(2024, 1, 15, 12, 40, tzinfo=UTC),
        show_progress=False,
    )
    print(report.downloaded, report.cached, report.failed)

asyncio.run(main())

The result separates downloaded, confirmed empty, cached and failed hours. A cooperative stop keeps completed results available for the next run.

!

Range length does not set transfer size. An uncached 12:30–12:40 request obtains the enclosing hourly file. Reading later applies precise start-inclusive, end-exclusive bounds.

03 · READ AND DECODE

Read just the interval you need

Use the iterator to keep memory bounded. Each frame contains at most batch_size rows. Choose serial decoding for the simplest setup or thread/process decoding for parallel work.

STREAMING PYTHON
from tick_vault import iter_tick_data

for frame in iter_tick_data(
    "EURUSD", start, end,
    backend="thread", max_workers=4,
    max_pending=8, batch_size=100_000,
    show_progress=False,
):
    analyse(frame)
TimeUTC-naive pandas timestamps
PricesInstrument pipet scaling
VolumesInteger millionths
Duplicate timesPreserved as distinct ticks

Strict reads require coverage for every overlapping hour. Use strict=False to clip to known coverage and skip unresolved hours. Missing or corrupt files marked downloaded remain visible errors.

04 · INTERRUPTIONS

Save and resume a managed job

Managed jobs persist their range, settings, completed work and next eligible time. Waiting jobs do not run in the background; resume them when the recorded deadline passes.

ASYNC PYTHON
from tick_vault import submit_download_job, resume_download_job

job = await submit_download_job("EURUSD", start, end)
print(job.state, job.completed, job.pending)

# Later, after the next eligible time:
job = await resume_download_job(job.job_id)

States distinguish queued, running, waiting_for_provider, waiting_for_network, paused, complete and needs_action. Completion requires no pending or failed hours.

05 · COMMAND LINE

Use the CLI

Use tick-vault or python -m tick_vault. Explicit times and a chosen base directory make local storage predictable.

EXAMPLES
# One permitted request, zero retries
python -m tick_vault canary EURUSD 2024-01-02T12:00Z --base-directory ./ticks --json

# Inspect local provider status; no HTTP
python -m tick_vault provider-status --json

# Run, inspect and resume a durable job
python -m tick_vault download EURUSD 2024-01-02 --end 2024-01-03 --base-directory ./ticks --managed --json
python -m tick_vault job-status JOB_ID
python -m tick_vault resume JOB_ID

# Read a local time window
python -m tick_vault read EURUSD --start 2024-01-02T12:30Z --end 2024-01-02T12:32Z

JSON reports completeness and partial progress. Ctrl-C requests a cooperative stop and preserves completed hours.

06 · STORAGE AND EXPORT

Export for analysis

SQLite is included and indexed by symbol/time. HDF5 requires PyTables; CSV is available from the CLI.

PYTHON
from tick_vault import export_sqlite, iter_sqlite

rows = export_sqlite("ticks.sqlite", "EURUSD", start, end)
for frame in iter_sqlite("ticks.sqlite", "EURUSD", start, end):
    analyse(frame)
CLI
python -m tick_vault export EURUSD ticks.sqlite --format sqlite
python -m tick_vault export EURUSD ticks.h5 --format hdf5
python -m tick_vault export EURUSD ticks.csv --format csv

SQLite and HDF5 support replace, append and fail modes. CSV supports replace and fail. Append preserves duplicates; HDF5 appends must be chronological. A failed export preserves the previous output file.

07 · LOCAL FILES

Know what is stored

The base directory contains raw hourly .bi5 files, metadata and logs. Shared provider controls, jobs and validated receipts use a separate per-user directory.

VAULTtick_vault_data/downloads/Raw hourly archive
VAULTtick_vault_data/metadata.dbHour status and source identity
STATE%LOCALAPPDATA%/TickVault/provider/Shared state on Windows
STATE~/.local/state/tick-vault/provider/Shared state on Linux/macOS

Cooperating local TickVault processes share this budget. Other applications and machines do not automatically participate.

RESILIENCE · RATE LIMITS · DATA QUALITY

Reliability & access

A resilient client can pace its own requests, respect observed pauses and protect local data. It cannot make an external provider available.

THE IMPORTANT LIMIT

What happens when the feed says 429?

HTTP 429 means the server or an intermediary is limiting requests. It might count by IP, account, route, resource or a wider service policy. A response alone rarely reveals which.

TickVault saves the pause, stops its retry wave and waits before admitting a single recovery probe. It does not switch IPs or rotate endpoints to bypass a restriction. A different route is suitable only when the provider's policy confirms an independent allowance.

!

No library can promise zero future 429s or zero errors. Provider rules, shared network traffic, service availability and local disk conditions are outside TickVault's control.

By default, uncached multi-hour downloads require a successful one-hour access check first. The canary makes at most one GET, with no automatic retry. Fully cached ranges remain readable and exportable locally.

SHARED ADMISSION

Controls that prevent avoidable requests

Cooperating TickVault operations use durable local provider state. Each HTTP attempt, including a retry, needs a lease. Defaults start conservatively:

ControlDefaultEffect
Start spacing2 secondsPrevents bursts
In flight1 requestCaps concurrency
Rolling budget30 per minuteLimits recent starts
Rolling budget1,800 per hourLimits hourly starts
No-header pause15 minutesFallback after a throttle
Retry wait60 secondsLonger delay is saved for later

These values are client ceilings, not a published Dukascopy allowance. Processes share the most restrictive saved settings. After a throttle, the client extends its pause and lowers its request rate.

State is local to one machine. Other software, users and machines sharing the network do not participate automatically.

VISIBLE, RESUMABLE OUTCOMES

Keep progress when a request cannot finish

A strict download reports its partial progress with an error. Managed jobs persist progress and their current state for inspection.

WAITING FOR PROVIDER

A cooldown or request budget has not cleared. Next eligible time is recorded.

WAITING FOR NETWORK

A temporary connection or server failure needs a later retry.

PAUSED

A cooperative stop preserved the completed hours.

NEEDS ACTION

Access, source, corruption or storage needs attention.

COMPLETE

Every requested hour is complete or confirmed empty.

QUEUED

Saved work has not started. Jobs do not schedule themselves.

Resume a waiting job after its saved deadline with tick-vault resume JOB_ID. If a process exits before publishing a shared-hour receipt, a later permitted request may be needed for that hour.

LOCAL DATA SAFETY

Validate before trusting the cache

Payloads are decompressed within bounds, then checked for record alignment, timestamps, hour limits and valid volumes. Invalid content is not published as a successful tick file. Valid writes use atomic publication.

  • Downloaded, confirmed empty and failed hours have separate metadata states.
  • Missing or changed files are rechecked when the range resumes.
  • A valid file left by an interrupted metadata update can be recovered without a new request.
  • Failed export preserves the previous output.
  • Vault identity is pinned to its configured feed.

Size and modification time speed up warm resume but are not cryptographic proofs. Shared receipt reuse also checks a digest and payload validity.

GUARANTEES WITH A BOUNDARY

What can be promised?

✓  Fully cached, validated range
Reading it makes no provider request, so it cannot receive a provider 429.

◷  Two-minute query
Local filtering is two minutes; a cache miss can still fetch one whole hourly file.

↗  Uncached range
Requests follow local limits, while provider availability and quotas remain external.

Dukascopy's documented Requester Pays daily S3 route has a different protocol, requires credentials and billing, and is not an automatic fallback here. Another source needs separate authorization, provenance and validation.
